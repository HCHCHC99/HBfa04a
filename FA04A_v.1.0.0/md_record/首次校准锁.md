# 首次校准锁（0x3716）

## 一、设计背景

关窗过流校准依赖角度区间检测（见《关窗过流校准阈值.md》）：实时角度必须在 [0x272A, 0x2729] 区间内才执行校准。

问题：**新烧录的设备**，程序里固化的默认角度不可信，第一次关窗过流时的实时角度很可能不在区间内，导致校准永远无法完成，基准点无法建立。

解决方案：增加"首次校准开关"寄存器 0x3716。开关为 1 时，第一次关窗过流**跳过角度区间检测，直接认定有效**并执行完整校准；校准完成后开关自动清 0，之后永久恢复常规区间检测。

---

## 二、寄存器

| 寄存器 | 地址 | R/W | 类型 | 默认值 | 说明 |
|--------|------|-----|------|--------|------|
| 首次校准开关 | 0x3716 | R/W | uint16 | 1（由宏决定） | 0=常规角度区间检测；1=首次关窗过流免检测直接校准 |

- 地址宏：`REG_FIRST_CALIB_EN`（App_Params.h）
- 烧录默认值由宏 `PARAM_DEFAULT_FIRST_CALIB_EN` 决定（App_Params.h，当前为 1）
  - 宏为 1：烧录后即处于首次校准模式，第一次关窗过流强制校准后自动清 0 存 Flash，掉电保持
  - 宏为 0：烧录后始终执行常规检测
- 存储位置：Flash 扇区 62-56（`AppParamRecord_t` 成员 `first_calib_en`）
- 写入校验：Modbus 写入只允许 0/1，其他值返回异常码（0x04）

## 三、程序逻辑

```
关窗(REV)过流 → RunAngle_TryCalibrate()
  │
  ├─ first_calib_en != 0 ?（0x3716 旁路检查，函数入口处）
  │   YES → 跳过角度区间检测，直接返回 true（首次校准锁生效）
  │
  └─ NO → 常规判断：calib_lower ≤ angle ≤ calib_upper ?
        YES → return true
        NO  → return false（后续走过流故障）

TryCalibrate 返回 true 后（dev_rturn.c 4 个校准点统一路径）：
  ├─ g_s32HallPulseAccum = 0（脉冲清零）
  ├─ fCurrentAngle = fMinAngle
  ├─ RunAngle_OnCalibration()
  │     ├─ s_abs_offset_x10 = 0x271C值，g_AbsAngle 同步
  │     ├─ Param_Save → Flash 扇区 55（关窗基准点）
  │     └─ ★ 首次校准锁清理：
  │           ├─ first_calib_en = 0
  │           └─ Modbus_SaveParams() → Flash 扇区 62-56
  ├─ 不报故障
  └─ 仅单向锁定（REV 方向）— RTURN_LIMIT_REV
```

清 0x3716 放在 `RunAngle_OnCalibration()`（校准真正完成时）而非 `TryCalibrate()` 旁路瞬间——若旁路后校准流程异常中断，开关不会被白白消耗。

**Modbus 写 0x3716**：走普通参数写路径 → `Param_WriteByReg`（0/1 校验）→ `Param_Save` 立即存 Flash + `App_ReloadConfig`。手动写 1 可随时重新进入首次校准模式。

## 四、代码调用链

```
dev_rturn.c（4 个校准点，全部经 TryCalibrate 闸门覆盖）
  ├─ 校准点 1（轮询，首次+重复）：RTurn_UpdateAngle
  ├─ 校准点 2（轮询，仅重复）：RTurn_UpdateAngle，锁释放重检
  ├─ 校准点 3（EventBus，首次）：RTurn_HandleOvercurrent
  └─ 校准点 4（EventBus，重复）：RTurn_HandleOvercurrent
       ├─ FWD(开窗)过流 → 直接故障，与 0x3716 无关
       └─ REV(关窗)过流 → RunAngle_TryCalibrate()

RunAngle_TryCalibrate()（App_RunAngle.c）
  └─ 入口旁路检查 first_calib_en

RunAngle_OnCalibration()（App_RunAngle.c）
  └─ 末尾清开关 + Modbus_SaveParams()（App_Modbus.c）

Modbus_SaveParams()：App_Modbus.c 新增接口
  └─ 复用扇区 62-56 的 Param 实例（m_stcParamConfig/m_stcParamRuntime），
     避免第二套 param_manager 实例管理同一缓冲区
```

## 六、生命周期

| 阶段 | 行为 |
|------|------|
| 烧录后首次上电 | `AppParamRecord_t` 结构体变大 → 旧 Flash 记录校验失败 → 默认值写入（first_calib_en=1），node_id 等需重新配置 |
| 第一次关窗过流 | 旁路检测 → 校准执行 → 开关自动清 0 并存 Flash；不报故障、仅单向锁 REV |
| 之后的关窗过流 | 开关为 0 → 正常角度区间检测（[0x272A, 0x2729]），区间外报故障双向锁死 |
| 掉电再上电 | Flash 中为 0，保持普通逻辑 |
| Modbus 手动写 1 | 立即存 Flash，重新进入首次校准模式 |

---

## 七、注意事项

1. **OnCalibration 里连写两个 Flash 扇区**（55 + 62-56）：过流事件路径耗时略增（几十 ms 量级）；调用点均在主循环上下文（轮询 + EventBus 主循环发布），不在 ISR，安全
2. **写非法值（>1）异常码为 0x04**（从设备故障），与现有其他寄存器写失败行为一致
3. **首次烧录后所有 62-56 参数恢复默认**（结构体校验失败导致），与之前新增 0x2729/0x272A 字段时情况相同
4. 读取逻辑用 `first_calib_en != 0` 判断，非 0 值等效于启用（理论上 Flash 只可能是 0/1，属于防御性写法）
